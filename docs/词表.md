# Engine_0 词表：术语、语义与结构体字段

> **范围**：`Engine_0` 主工程（资产层、渲染图描述/前端/后端、RHI）与 `examples/`、`tests/` 中公开的数据结构。
> **依据**：以当前源码注释与字段默认值为准，辅以 `README.md`、`Engine_0/RenderGraphFrontend.md`、`Engine_0/rhi/README.md`。
> **不在范围**：第三方头文件（`external/`）、Vulkan 原生类型本身、纯函数实现细节。
> **读法**：
> - 树中每个节点是一个词或一个结构体；`字段` 节点给出类型与语义。
> - `→` 表示“解析为 / 映射到 / 产生”。
> - “别名”列的是同一概念在代码中的其他叫法；“易混”指向第 9 节。
> - 行内 `file:line` 是定义位置，链接指向仓库内相对路径。
>
> **维护规则**：字段增删、默认值改变、术语改义时同步本文件；本文件只描述“是什么”，不复制实现步骤。

## 1. 跨板块基础词表

```text
Engine_0 通用词
├─ 分层
│  ├─ 资产层        逻辑路径/逻辑名解析，屏蔽磁盘与内存包差异
│  ├─ 前端层        逻辑声明、隐式版本化、模块编译与实例化、Lower
│  ├─ 渲染图        资源/Pass 拓扑、子资源屏障、多队列切批、Host/Transfer/Mux/Present
│  └─ RHI 层        Vulkan 1.3 封装：Device/资源/管线/描述符/命令/同步/交换链
├─ 声明生命周期
│  ├─ 声明 Declare     在 Builder 上写资源、Pass、拓扑；不接触 Device
│  ├─ 降低 Lower       纯函数：分配隐式版本、补数据边、产出 LoweredGraph
│  ├─ 构建 Build       把 Lower 结果写入 RenderGraph；只写声明
│  ├─ 注册 ProcessRegister  名称对账、注册期校验、回填 id/版本
│  ├─ 实化 Realize     创建 RHI 资源、管线、描述符，编译屏障
│  ├─ 录制 Record      逐 Pass 先发屏障批，再录命令
│  └─ 提交 Submit      按队列切批；跨队列用信号量；Host 段异步执行
├─ 资源身份
│  ├─ 逻辑名 logical name      用户书写的资源名，如 "Color"
│  ├─ 版本 version             同一逻辑名每次写入递增；读未写资源为导入版本 v0
│  ├─ ResourceRef             (name, version) 二元组，Lower 后的资源身份
│  ├─ 图资源名 graphResourceName  参与图内对账的名字（模块实例化可改写）
│  ├─ SPIR-V 变量名 resourceName  着色器反射对账用的变量名
│  ├─ 资产键 asset key         资产清单键，不是图资源名
│  ├─ 逻辑路径 logical path    相对 ContentResolver 的路径，如 "assets/skyview.jpg"
│  └─ 身份 identity            缓存/去重键："fs:<绝对路径>" 或 "pack:<hash>:<逻辑路径>"
├─ 所有权
│  ├─ Own             引擎按 Desc 创建并销毁
│  ├─ Borrow          只包装外部句柄，不创建、不销毁
│  ├─ Borrow-later    先有 Desc，句柄运行期 retarget 填入（Mux 输出）
│  └─ External        外部来源的生命周期由宿主管理（图只建模）
├─ 同步
│  ├─ 屏障 barrier            执行依赖 + 内存可见性 + 布局转换
│  ├─ 布局 layout             图像子资源状态：Undefined/General/ColorAttachment/...
│  ├─ 子资源 subresource      (mipLevel, layer) 及其范围
│  ├─ 批 batch                同一队列连续提交的一段 Pass 区间
│  ├─ 跨队列 release/acquire  生产批尾 release + 消费批头 acquire
│  ├─ 帧槽 frame slot         多帧在飞的独立 mux 选择与描述符集
│  └─ 跨帧 crossFrame         资源活过多帧；帧首闭环上帧末次使用
├─ 选择与执行控制
│  ├─ mux             零命令选择点；候选按帧槽 retarget，换绑不重编译
│  ├─ 别名 alias      多个资源共享同一内存块；图只校验寿命，失败降级不终止
│  ├─ 就地读写 inPlace  同一 Pass 内同一资源既读又写；须在 reads∩writes
│  └─ 执行层 gate    SetPassActive 运行期裁剪 Pass；有活跃读者时拒绝关闭写者
└─ 模块
   ├─ 模块 module        逻辑声明的只读快照，可嵌套实例化
   ├─ 端口 port          模块内部资源对外的 Input/Output/Inout 视图
   ├─ 固定引用 fixed     模块自带、不经父端口的外部资源
   ├─ 标签 tag           实例化作用域前缀，内部名加 tag
   └─ 入口/出口 entry/exit  模块内供父拓扑接线的首/末 Pass 名
```

### 1.1 一句话语义

| 词 | 语义 | 反例 / 边界 |
|---|---|---|
| **声明** | 只描述“谁读写什么”，不创建 GPU 对象 | 声明阶段的 `resourceId` 尚未回填 |
| **Lower** | 把用户逻辑声明变成带版本的 `LoweredGraph` 的纯函数 | 不接触 `Device`；失败目标图保持空 |
| **Build** | 把 Lower 结果注册进 `RenderGraph` | 不等于 Realize；此时还没有 GPU 句柄 |
| **ProcessRegister** | 名称对账、类型/用途校验、id 与版本回填 | 不是拓扑排序；排序在 `GenerateSubmitSequence` |
| **Realize** | 创建 RHI 资源/管线/描述符并编译屏障 | 未实化资源被引用会抛异常 |
| **版本** | 写入序号的逻辑代次，用户不显式书写 | 与资产 `revision`（mtime/size）不是一回事 |
| **Use / Usage** | 一次访问的用途（读/写/附件/传输…） | 不是资源创建能力位 `ImageUsage/BufferUsage` |
| **批** | 同队列、连续 `submitSeq` 区间 | 不是“一个 Pass”；一批可含多个 Pass |
| **帧槽** | 多帧在飞的槽位状态 | 不是附件 `slot`，也不是静态纹理堆槽位 |

## 2. 资产层

### 2.1 术语树

```text
资产层
├─ ContentResolver
│  ├─ Mount(prefix, root)     前缀 → 根目录；最长前缀优先
│  ├─ FallbackRoot            无前缀路径的兜底根（发布期资源包）
│  ├─ SetPack(pack)           挂载非拥有内存包；仅 pack: 路径查包
│  ├─ scheme                   File / Pack；pack: 前缀显式走内存包
│  ├─ 规范化 Normalize         统一分隔符、折叠空段与 "."、拒绝绝对路径与 ".."
│  ├─ Resolve                 逻辑路径 → Resolved（绝对路径/身份/大小/哈希/mtime）
│  ├─ ViewBinary              零拷贝切片，仅内存包；磁盘源返回 nullopt
│  └─ ReadBinary              统一读取（磁盘或包内拷贝）
├─ ShaderLibrary
│  ├─ ShaderEntry             逻辑名 → 阶段/逻辑路径/入口点/defines
│  ├─ 阶段推断                显式 stage 优先，否则按扩展名（.vert/.frag/.comp…）
│  ├─ Resolve                 逻辑名 → rhi::ShaderStageDesc
│  ├─ Revision                mtime/size 变更信号（不自动重编译）
│  └─ Manifest                JSON 清单，构建期 glslc 产物登记
├─ AssetCatalog
│  ├─ ImageAsset              资产键 → 图像来源 + 创建参数
│  ├─ BufferAsset             资产键 → 缓冲来源 + 创建参数
│  ├─ AssetRevision           mtime/size/hash 变更信号
│  └─ Validate                逐条经 ContentResolver 解析，缺失/非法路径报错
├─ AssetLoader
│  ├─ AcquireImage/Buffer     资产键 → GPU 句柄；按绝对路径缓存
│  ├─ 描述一致性              同路径重复获取时描述须一致，否则拒绝复用
│  └─ ResolveIdentity         只解析身份不加载
├─ AssetPack
│  ├─ DENGPAK1                单文件整包，整包读入内存，按索引切片
│  ├─ Entry                   offset/size/hash/flags（flags=0 raw，压缩预留）
│  └─ View/Read/Stat          包内逻辑路径 → 切片/拷贝/元数据
└─ ModulePack
   ├─ 依赖收集                从模块文档提取 shaderRefs 与 asset 键
   └─ ModulePackResult        moduleName/shaderRefs/assetKeys/inputs/bytes
```

### 2.2 结构体字段

#### ContentResolver（[ContentResolver.h](../Engine_0/ContentResolver.h#L16)）

```text
ContentResolver
├─ Resolved（一次解析结果）
│  ├─ kind: Kind(File|Pack)          来源种类；决定 absolutePath 是否有值
│  ├─ absolutePath: optional<path>   仅 File 源有值；Pack 源为空
│  ├─ identity: string               缓存/去重键："fs:<abs>" 或 "pack:<hash>:<logical>"
│  ├─ logicalPath: string            规范化后的逻辑路径，保留 pack: 头
│  ├─ size: uint64                   字节数
│  ├─ hash: uint64                   包索引提供；文件源为 0
│  └─ mtime: uint64                  最近写入时间（毫秒）；同平台可做变更检测，不保证 Unix epoch
├─ ParsedPath（ParsePath 的纯语法结果）
│  ├─ scheme: Scheme(File|Pack)      路径方案
│  └─ logical: string                剥离 pack: 后的规范化路径
└─ MountPoint（私有）
   ├─ prefix: string                 逻辑路径第一段
   └─ root: path                     该前缀对应的磁盘根
```

#### AssetCatalog（[AssetCatalog.h](../Engine_0/AssetCatalog.h#L17)）

```text
AssetCatalog
├─ ImageAsset

│  ├─ srgb: bool                     解码时是否按 sRGB 处理（宿主提示）
│  ├─ flipY: bool                    解码时是否上下翻转（宿主提示）
│  └─ generateMips: bool             是否由加载器生成 mip 链
├─ BufferAsset
│  ├─ name: string                   清单键
│  ├─ logicalPath: string            来源路径
│  ├─ usage: BufferUsage             创建能力位
│  ├─ hostVisible: bool              是否主机可见（决定内存类型）
│  └─ byteSize: uint64               0 = 整个文件
└─ AssetRevision
   ├─ mtime: uint64                  修改时间
   ├─ size: uint64                   文件大小
   └─ hash: uint64                   包索引提供；文件源为 0
```

#### ShaderLibrary（[ShaderLibrary.h](../Engine_0/ShaderLibrary.h#L16)）

```text
ShaderEntry
├─ name: string                      逻辑键，如 "blur.comp"
├─ stage: optional<ShaderStage>      空 = 按 logicalPath 扩展名推断
├─ logicalPath: string               相对 ContentResolver，如 "shaders/blur.comp.spv"

```

## 3. 前端层：声明、Lower、模块、文档

### 3.1 术语树

```text
前端层
├─ 声明 Declare
│  ├─ DeclareImageResource    自建 / 借用句柄 / 资产键三种入口
│  ├─ DeclareBufferResource   同上；资产键需 loader
│  ├─ DeclarePass             读写集可从 PassDesc 推导，或显式给出
│  ├─ inPlace 集              同 Pass 就地读写；必须 ⊆ reads ∩ writes
│  ├─ DeclareTopology         顺序边、Then、ThenAll；只追加不覆盖
│  ├─ AliasLogicalResources   硬契约：同类型/同描述/同视图，不满足直接报错
│  └─ DeclareStaticTexture    按声明顺序分配静态纹理堆槽位
├─ 降低 Lower
│  ├─ 隐式版本                 读未写 = v0；每次写生成下一版本
│  ├─ 数据边                   读边/写边补出的依赖边（带警告记录）
│  ├─ 顺序边                   用户声明；只参与定序，不替代数据依赖
│  ├─ 矛盾诊断                 成环、读写倒置、多写者未定序
│  ├─ 别名组                   手动分桶；Lower 只验证，不决定内存
│  └─ LowerResult              ok + 拓扑报告 + 诊断 + 版本表 + LoweredGraph
├─ 模块 Module
│  ├─ CompileModule           声明 → 只读快照；封闭世界、无环、多写者定序
│  ├─ 端口 Port               Input / Output / Inout，必须是已声明 owned 资源
│  ├─ 固定引用 Fixed          模块自带外部资源，按身份收敛为父级唯一声明
│  ├─ Instantiate             按 tag 作用域拷贝展开；父 Builder 统一 Lower 一次
│  ├─ Entries / Exits         模块内部入口/出口 Pass（已作用域化）
│  └─ ThenAll                 集合间全连接边，把实例接入父拓扑
├─ 合并 Import / Merge
│  ├─ ImportDeclarations      声明期并入；失败本 Builder 保持原状
│  ├─ passPrefix              追加图 Pass 名前缀
│  └─ dedupIdenticalResources 同名且描述完全一致时自动合一
└─ 文档 Document
   ├─ Capture                 抓取声明快照；外部资源只记标记
   ├─ Save / Load / Restore   声明层 JSON；句柄与回调由宿主注入
   ├─ 规范化 JSON             字段顺序固定，便于 diff 与 round-trip
   └─ 不落盘                  注册期回填字段、运行期 mux 选择、DrawSource、回调
```

### 3.2 结构体字段

#### 诊断与 Lower（[RenderGraphBuilder.h](../Engine_0/RenderGraphBuilder.h#L33)）

```text
BuilderEdge
├─ from: string                边的起点 Pass 名
└─ to: string                  边的终点 Pass 名

BuilderDiagnostic
├─ severity: BuilderSeverity   Warning | Error
├─ kind: BuilderDiagKind       诊断类别（见下）
├─ message: string             人类可读原因
```

```text
├─ byteSize: uint64            仅 BufferToBuffer 使用；0 = 整段

├─ bufferImageRegions: vector<BufferImageCopyRegion> 区域拷贝
├─ imageRegions: vector<ImageCopyRegion> 区域拷贝
├─ blitRegions: vector<ImageBlitRegion>  blit 区域

├─ alternatives: vector<string> 候选逻辑名；顺序即选择索引
└─ alternativeIds: vector<uint32> ProcessRegister 回填的候选资源 id

└─ 空结构：只表达“转 PresentSrc”这一收尾职责

```

### 5.1 术语树

```text

│  ├─ PassOrder        after/before 只追加边，不覆盖数据依赖

├─ 切批与提交

│  ├─ FrameSlotState   每槽 mux 选择、描述符集、跨队列信号量、帧序号
│  ├─ MuxEntry         输出资源 + 候选 id 列表
│  └─ Retarget         交换链重建/选择变化时只换句柄，不重编译

```

```text
└─ draw: DrawSource              绘制数量来源
```

`BuildMeshDrawData` 在创建/上传阶段调用：先 `Mesh::Validate`，再匹配所需语义与格式，最后把源 binding 压紧为 `0..N-1`；失败时 `output` 保持原值。`ValidateMeshPipeline` 只校验布局与管线一致，不创建缓冲、不注册 Pass、不反射 shader。

## 9. 易混词对照

| 易混对 | 区分 |
|---|---|
| **资源 vs 资产** | 图资源由 `RenderGraph` 管理、有逻辑名与版本；资产是 `AssetCatalog` 的清单条目，按资产键索引。资产可被声明为图资源，但二者不是同一身份。 |
| **逻辑名 vs 图资源名 vs SPIR-V 变量名** | 逻辑名是用户资源名；图资源名参与图内对账（模块实例化可改写）；SPIR-V 变量名是反射对账用的着色器变量名。 |
| **Pass vs 节点** | `Pass` 是抽象基类；`RenderPass/ComputePass/.../MuxPass` 是具体节点。代码中“节点”与“Pass”常混用，正式文档用“Pass 节点”。 |
| **声明 vs 注册 vs 实化** | 声明只写 Builder；注册做名称对账与校验；实化才创建 GPU 对象。三者失败后的状态不同。 |
| **Usage vs ImageUsage/BufferUsage** | `Usage` 是逐次访问用途；`ImageUsage/BufferUsage` 是资源创建能力位。前者不能替代后者。 |
| **version vs revision vs frameSerial** | 资源 `version` 是写入代次；`AssetRevision/ShaderRevision` 是 mtime/size 变更信号；`frameSerial` 是帧槽帧序号。 |
| **slot（四种）** | `AttachmentBinding::slot` 是颜色附件序号；帧槽 frame slot 是在飞帧索引；静态纹理堆槽位是 set 0 数组下标；`Submesh::materialSlot` 是材质逻辑槽。 |
| **batch（两种）** | `QueueBatch` 是提交批（同队列 submitSeq 区间）；`BarrierBatch` 是一组屏障。说“批”时须加限定。 |
| **binding（四种）** | 描述符 binding（set/binding）、附件绑定 `AttachmentBinding`、顶点流 binding、`ShaderBinding`（描述符声明）。 |
| **layout（三种）** | `ImageLayout` 是子资源状态；`initialLayout` 是链首布局；`m_passImageLayouts` 是每 Pass 目标布局。 |
| **external vs borrowed vs borrowedLater** | `external` 表示生命周期来源在外部；`borrowed` 表示节点只包装不拥有；`borrowedLater` 表示句柄运行期才填入。三者可同时出现。 |
| **lower vs build vs realize** | Lower 纯函数产出声明图；Build 写入后端图；Realize 创建对象。 |
| **resolve（三种）** | `ProcessRegister` 做名称/类型对账；`ResolveShaderRefs` 把逻辑名解析成 SPIR-V；`ResolvePassDesc` 把 Desc 内名字解析到版本/id。 |
| **mux prepare vs select** | `MuxPrepare` 只把候选转到可采样布局（无内存读写）；`MuxSelect` 是虚拟写，不产生布局转换。 |
| **hostVisible vs HostRead/HostWrite** | `hostVisible` 是内存属性；`HostRead/HostWrite` 是 Host Pass 的访问用途。 |
| **indices vs index stream** | `IndexData` 是 Mesh 的 CPU 索引数据；`IndexStreamBinding` 是 Pass 的 GPU 索引流绑定；`IndexedRange` 是子网格绘制范围。 |
| **vertexOffset vs firstVertex/firstIndex** | `DrawSource.vertexOffset` 只在索引绘制时加到索引值；`firstVertex/firstIndex` 是起始元素。 |
| **count（DrawSource）** | `Direct` 时是顶点/索引数；`Indirect` 时是 draw 条目数。 |
| **byteSize（Transfer）** | 仅 `BufferToBuffer` 使用；其他方向由区域描述或整段语义决定。 |
| **mipLevels=0** | `ImageAsset::mipLevels` 的 0 表示“加载器补齐完整链”；`ImageDesc::mipLevels` 默认 1，`ImageSubresourceRange` 的 count=0 表示“补齐到末尾”。三个 0 的语义不同。 |

## 11. 语义边界与维护提示

1. **`Usage::Auto` 不是“无用途”**：它表示由绑定位置与资源类型推断；推断规则写死在 `Resolve*PassDesc` 与 `Validate*` 中，新增 Pass 类型时必须同步。
2. **`ImageDesc::depth` 与 `arrayLayers` 正交**：3D 深度与数组/Cube 层数不能互相替代；`viewType` 决定解释方式。
3. **`crossFrame` 是资源级承诺**：帧首闭环上帧末次使用；不是“每帧自动清空”。与帧槽数量、描述符刷新是不同机制。
4. **`external` 资源图只建模不拥有**：布局与跨帧策略由父级/宿主决定；端口与固定引用收敛时只校验类型与单向 `crossFrame` 约束，不要求 Desc 逐字段相等。
5. **`StaticTextureDecl::asset` 与 `ModuleFixedResource::asset` 只用于文档/打包**：不参与运行期解析；运行期靠注入句柄或 `AssetLoader`。
6. **`ShaderBinding::offset/range` 对图像无意义**：仅 Buffer 描述符窗口；图像子资源由 `view`/`range` 表达。
7. **`ShaderBinding::set/binding/arrayCount` 是反射回填**：注册期不填；手工填写不会替代 `RealizePass` 的对账。
8. **`MuxPassDesc::alternativeIds` 是注册期回填**：版本化后不再按名查表；运行期选择只存索引。
9. **`FrameSync` 只表达交换链两端的信号量**：跨队列同步由 `SubmitPlan` 内部的 timeline/二进制信号量完成，二者不要混用。
10. **`AssetLoader` 缓存按绝对路径/身份而非资产键**：同一文件被多个资产键引用时复用同一 GPU 句柄，但描述必须一致；描述不一致会拒绝复用。
11. **错误码是终止性的**：`RenderGraph::HandleError` 打印后结束进程；不要把它当作可恢复异常使用。
12. **本文档与 `CONTEXT.md` 的分工**：本文件是面向本仓库的“术语 + 结构体字段”参考，允许出现实现路径与 API 清单；`CONTEXT.md`（若建立）只保留领域词与关系，不复制字段表。
